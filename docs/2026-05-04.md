## OFFICIAL BLOGS

**Anthropic Engineering: Scaling Managed Agents — Decoupling the brain from the hands**

The takeaway: Anthropic built Managed Agents by solving an old computing problem — designing a system flexible enough for "programs as yet unthought of." Their solution mirrors how operating systems virtualized hardware decades ago.

The core architecture decouples three components that were traditionally coupled: the session (append-only log), the harness (the loop calling Claude), and the sandbox (where code runs). Each is now independent — the harness calls the sandbox via execute(name, input) → string, treating it like any other tool. The container becomes "cattle" rather than a "pet."

Key technical wins: p50 time-to-first-token dropped ~60%, p95 dropped over 90% — because inference starts immediately without waiting for container provisioning. If the container dies, the harness catches it as a tool-call error and re-provisions on demand.

Security insight: In the old coupled design, prompt injection only had to convince Claude to read its own environment. Now, tokens are never reachable from the sandbox — Git uses repo-specific tokens during sandbox init, and MCP OAuth tokens live in a secure vault, accessed via a dedicated proxy.

The future vision: "Managed Agents is a meta-harness... unopinionated about the specific harness that Claude will need in the future." Claude Code is one example; task-specific harnesses are another.
[https://www.anthropic.com/engineering/managed-agents](https://www.anthropic.com/engineering/managed-agents)
